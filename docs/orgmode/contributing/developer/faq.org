* Developer FAQ

** Why are chemfiles and readcon optional?

seams-core already detects both. =with_chemfiles= and =with_readcon=
here are the same feature options, passed through to the subproject.
When the library is found, seams-core adds =SEAMS_HAS_CHEMFILES= or
=SEAMS_HAS_READCON= to =yds_dep= and =src/bindings.cpp= exports
=readChemfiles= or =readCon=. When it is not found, configuration still
succeeds and the loaded module reports the reader as absent.
=has_chemfiles()= and =has_readcon()= read that report.
The bindings do not reimplement either parser.

** Why does =cog= not write =CHANGELOG.md=?

=cog.toml= sets =disable_changelog = true=. towncrier owns
=CHANGELOG.md= and reads fragments from =changelog.d/=, which is the
directory this repository already uses. =cog bump= runs
=towncrier build --yes --version {{version}}= from =pre_bump_hooks=.

** Where is the version written?

=[project].version= in =pyproject.toml= is the source.
=ci/version/pydseams_version.py= reads it for cogapp.
=ci/version/files.txt= lists the copies: =meson.build=,
=src/pydseams/__init__.py=, =tests/python/test_bindings.py=, and
=CITATION.cff=. =docs/source/conf.py= reads =pyproject.toml= itself, so
it is not a copy. Regenerate with

#+begin_src bash
python -m cogapp -r -I ci/version @ci/version/files.txt
#+end_src

Check with =python -m cogapp --check -I ci/version @ci/version/files.txt=.
Call cogapp as =python -m cogapp=. The =cog= executable is cocogitto.

** Why is the release document Org mode?

The reader manual is Org mode. The release path is the same format, in
this directory, and is not exported to the reader site. There is no
=RELEASING.md=.

** What publishes a release?

A tag =vX.Y.Z= whose name equals =v= plus =pyproject.toml='s version
runs =.github/workflows/build_wheels.yml=. That workflow builds the
sdist and the wheels and publishes them to PyPI with trusted
publishing. =cog bump= creates the commit and the tag. Pushing them is
the publish step. See [[file:release.org][release.org]].
